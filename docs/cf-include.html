cf-include

Fetch an HTML fragment, compose nested includes and slots, and replace the include element with fresh DOM. 

<cf-include src="./card.html">Loading card…</cf-include>

Attributes

src

URL · required
A non-whitespace HTTP(S) URL resolved against the entry document’s document.baseURI. No default. URL hashes are removed before requesting HTML; query strings remain. Nested paths use the same page base, including after redirects. See Paths and requests.

Children and slots

Children remain visible while loading and on failure. On success, cloned children are supplied to matching slots in the fragment; unmatched children are discarded. Nested includes in fallback content are not independently expanded before their owning include completes. Ordinary includes do not evaluate bindings; includes rendered inside a data template inherit its context.

Resulting DOM and timing

The wrapper is removed. By default, an include tree, including nested fragments, is prepared before insertion. Nested branches prepare sequentially in document order. Separate live outer includes start independently. Fetch completion order does not change DOM order, style precedence, or inline classic script activation order. Scripts activate after insertion; styles move to the head. Only the mounted outer tree emits the include load event, from its former parent. See Scripts and styles and Events and lifecycle.

Atomic mounting only

The former progressive attribute is ignored. A parent waits for every nested include before mounting. Put critical content in initial HTML or use separate live includes for independent loading. See migration notes.

Sequential branches, ordered activation

The second panel starts loading after the first branch has finished preparation. Their scripts run in document order only after the whole tree is ready, so the second panel can use the first panel’s inline classic helper. Network requests must not depend on another fragment’s script executing first.

Loading and failure

There are no state-template attributes for includes: use ordinary fallback children. An empty fragment successfully removes the wrapper and inserts nothing. In default atomic mode, a nested failure preserves the outer wrapper and its original fallback nodes, state, and listeners. Failure sets data-cf-error, emits cf:error, and logs a console error.

If one branch fails, later branches in that tree are not prepared and none of the failed tree mounts or activates scripts. There is no HTML request timeout. Successful and in-flight requests are cached; failed fetches are evicted. Create a new element to retry. Attribute changes and reconnection do not reload. Removed includes ignore late successful results; removal does not cancel fetches. See Compose reusable fragments.
