Slots

Insert supplied direct children into an include fragment at named or default slot positions. 

<slot name="heading"><h2>Default heading</h2></slot>
      <slot><p>Default body</p></slot>

Attributes

name

String · optional on slot
The slot name; omitted or empty means the default slot. Names are matched exactly.

slot

String · optional on supplied child
Selects a named slot for a direct child element. Omitted or empty means default. Text nodes always target the default slot. There is no separate required value.

Assignment and fallback

Each supplied element or text node goes to the first matching slot. Assigned nodes replace the slot; otherwise the slot’s own children replace it. Unmatched children and comments are discarded. Whitespace text counts as assignment and can suppress default fallback. Slots belonging to a nested include are left for that include.

There is no Shadow DOM distribution, slotchange event, or live reassignment. Slot wrappers disappear; assigned elements retain their slot attribute. In a data-rendered include, assigned content inherits the data scope.

DOM, timing, and failure

Assignment happens during include preparation, before the tree mounts. A failed tree retains the original include children. Outside CFJS includes, CFJS does not process slot elements. Follow Compose reusable fragments; see cf-include for request and failure behavior.
