Scripts and styles

Script activation

CFJS recreates active scripts once after mounting an include tree or successful data result. Scripts selected from data, loop, or conditional templates wait for this activation pass; unselected conditional branches remain inert. Attributes, nonce, and script text are copied; CFJS does not use eval. Inline classic scripts run in DOM order with the complete mounted tree present. Nested branches prepare sequentially; no branch activates early. Use a function wrapper to isolate each instance’s variables. The example’s fragment runs an inline script and loads ../scripts/examples/status.js, which marks its mounted section with data-external="ready". Edit either script and Run to try it.

Ordering and readiness

External classic scripts without async preserve insertion order relative to one another. Inline scripts do not wait for those external scripts. defer has no parser-time meaning on these dynamically created scripts. Async scripts follow native scheduling.

Modules are asynchronous. External modules evaluate once per resolved URL; inline module bodies run per inclusion. Template scripts remain inert and non-JavaScript data scripts remain data. Browser CSP, integrity, and native script rules still apply. Native script errors do not roll back markup or turn into include errors.

A source defined by an inline classic script in the same include is ready for its data elements. A source defined later by a module or external script may not be ready. cf:load is not a wait-for-all-assets event.

Styles

Active style blocks move into the document head before its first stylesheet link. Duplicate blocks are identified by trimmed CSS text and removed. Styles remain global and remain after their component disappears. Progressive sibling styles arrive in completion order; use page styles for predictable shared layout. There is no instance scoping or automatic cleanup. Ordinary linked stylesheets follow native browser behavior.
