Contributing

Development workflow

Use Node.js 22.19 or newer for the test tools. The documentation itself can be served by any static HTTP server without installing dependencies or building files. 

npm run docs:dev

      # To run browser tests:
      npm ci
      npx playwright install chromium
      npm test

Root cfjs.js is canonical. Both docs/vendor/cfjs.js and the sibling ../portfolio/src/vendor/cfjs.js are portable byte-identical copies, never cross-repository symlinks. Compare divergent copies before syncing. After runtime changes, run npm run docs:sync here, then npm run cfjs:sync and npm run cfjs:check in the portfolio. Run the library suite and portfolio unit and browser tests. Report unavailable sibling verification as outstanding.

Author documentation

Each root topic HTML file contains its content inside the components/shell.html include. Edit the topic in that one file. Reuse components for the shared shell and navigation; keep data, scripts, styles, examples, and vendor dependencies in their own folders. Keep reusable component markup before any scripts and styles.

Register topics in data/topics.json, preserve stable heading IDs. Navigation and previous/next links render with CFJS providers and templates. Keep runnable HTML and example-specific fragments in examples/, JSON in data/examples/, scripts in scripts/examples/, images in assets/, and shared example CSS in styles/examples.css.

Register runnable files in data/examples.json and reference their key with data-example. Manifest paths are relative to examples/, including supporting files such as ../data/examples/projects.json and ../scripts/examples/global.js. The first listed file is the HTML entrypoint in examples/. Browser JavaScript fetches these same files for source panels, so there is one source of truth. Use relative URLs in example HTML; the runtime and styles/examples.css are fixed preview dependencies.

Verify changes

Every public behavior change must update the reference, guides, README, runnable examples, browser coverage, and migration guidance when breaking.

Format HTML with npm run docs:format, or check it without changes using npm run docs:format:check. The pinned Prettier version formats HTML using its configured defaults. Run npm test. It verifies the docs runtime copy and serves source files directly for browser checks covering runtime behavior, topic links, copy and tabs, live examples, and desktop, tablet, and mobile layouts. Visually inspect affected pages too.

Set CHROMIUM_PATH for installed Chrome, or BROWSER=firefox / BROWSER=webkit when those Playwright browsers are installed. A passing run verifies only that engine. No benchmark or build tooling is required.

Repository and release preparation

This page documents the repository workflow. Browser suites can be run locally; no CI workflow is configured. Version 0.1.0 is pending release; licensing and release publication remain separate steps. The npm package stays private.

To host the documentation, serve the contents of docs/ unchanged on a static HTTP host. Relative URLs support subdirectory hosting. There is no deployment packaging command. Publish only when requested.
