Migration

Portfolio runtime alignment — November 14, 2026

The canonical runtime now matches the portfolio byte for byte. Progressive mounting, concurrent nested preparation, parsed-template caching, row-local source lookup, static-data skipping and assembled readiness events are removed. The compiler, static/assembly builds and server renderer have also been removed. Serve original HTML, fragments, JSON and the runtime directly. Remove compiled markers and restore the original data templates; generated output is not a replacement for source. Initialize ordinary page controls at DOM readiness and dynamic content on its own load event. Use global nested providers. That development snapshot used package version 1.0.0; release preparation now uses 0.1.0. The runtime embeds no release number.

Progressive includes removed

The portfolio runtime ignores progressive. Includes mount only after their entire tree is prepared; a nested failure preserves the outer fallback. Move critical content to initial HTML or independent outer includes.

From the includes-only snapshot

This development snapshot changes path semantics and adds data, loops, slots, and style handling. It is not a promise of compatibility with the original includes-only snapshot.

  1. Rewrite nested include and asset paths relative to the entry document. CFJS no longer rebases asset attributes against the fragment response URL.
  2. Check component style precedence: style blocks move to the head before the first stylesheet and identical blocks are deduplicated.
  3. Use slots for supplied include children. Unmatched children are discarded after a successful include.
  4. If migrating the portfolio’s interim registration API, replace CFJS.dataSources registrations with named global functions or window values and update source attributes. 
// Before: interim portfolio API
      CFJS.dataSources.set("projects", async () => data);
      // After
      window.loadProjects = async () => data;
      // Use source="loadProjects" in the data element.

Nested requests are sequential

Nested include branches now prepare sequentially in markup order. A failure prevents later branches in that tree from starting. Separate live includes remain independent. Scripts activate only after the complete tree mounts.

Data preparation is sequential

Data-template siblings and loop rows prepare sequentially. Each result mounts atomically; row scopes, style precedence and script order remain stable. Later siblings and rows do not prepare after a failure.

Documentation links

The old root hash links redirect to topic pages and matching anchors. Static topic URLs work without a router or server rewrites. This redesign changes no CFJS public runtime behavior.

Render yielding removed

An earlier development build yielded to the browser on an 8 ms budget while preparing includes and data renders. That scheduler has been removed: once its requests arrive, a render's detached preparation, mount and script activation run without CFJS-initiated yields. Existing markup needs no migration. Code that relied on other tasks running between a response and cf:load should listen for cf:load instead. Repeated includes parse cached response text afresh; preparation is sequential and mounting remains atomic. Keep large lists bounded in your application.

Nested sources are global only

Nested source paths now resolve only on window. Replace row-local sources with explicit global providers or render prepared row data directly with bindings, loops and conditions. A global with the same root as a row alias now wins. Result binding scopes remain independent.

Documentation served directly for v0.1

Serve docs/ as authored. The documentation build and deployment packaging commands have been removed; there is no generated dist/ site. Existing topic URLs are unchanged. Each root topic HTML file contains both its document setup and content, supplied directly to the shared shell. Separate pages/ fragments have been folded into their topic files. Reusable fragments live in components/, metadata in data/, and browser code, styles, and dependencies in their own folders.

Navigation and previous/next links use CFJS data templates. Example panels and heading links are prepared by browser JavaScript. Search indexes topic pages on first use. Documentation consumers need neither npm nor a build. Compare and synchronize docs/vendor/cfjs.js with npm run docs:sync after runtime changes; tests check equality.

The old performance audit commands and reports have been removed. Runtime behavior and runnable performance examples are unchanged.
