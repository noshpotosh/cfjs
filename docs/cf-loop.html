cf-loop

Repeat a direct child template for each array item inside a data rendering context. 

<cf-loop items="response.projects" as="project">
        <template><p cf-text="project.title"></p></template>
      </cf-loop>

Attributes

items

Property path · required
Must resolve to an array in the current context. Missing, null, and non-array values fail the owning data render. No default; no expressions or indexes.

as

Identifier · required
The local item alias, using the same identifier grammar as cf-data name. Each row inherits the parent context plus this alias; a duplicate alias shadows the inherited one. No default and no built-in index variable.

Child templates and scope

The first direct template without data-state is required and cloned for every item. Nested loops and included markup inherit the row context. A nested data element starts its own context. An ordinary loop outside a data template has no independent renderer.

Empty and failure behavior

The first direct template data-state="empty" is cloned for an empty array; without it, nothing is inserted. Empty markup is static: bindings and loops are not evaluated. There is no loop loading or error template. Invalid configuration and rendering errors use the owning data element’s error behavior.

Resulting DOM and timing

The loop wrapper and its templates are replaced with consecutive row nodes, in array order, during data rendering before mounting. There are no per-row load events. Results do not update when the array changes. Follow Repeat templates and cf-data.

Use cf-if to choose a branch once in the current data or loop context. Only the selected template is rendered; nested data keeps its own scope. Loading, error, and loop empty templates remain static.

Data-template siblings and loop rows prepare sequentially while detached. Rows retain array order and each row keeps its own binding context. The owning data element mounts only after all preparation succeeds; scripts and styles retain document order. Nested data and unselected templates stay inert until their normal lifecycle. A failed render never mounts partial results; later siblings and rows are not prepared.
