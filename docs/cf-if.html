cf-if

Choose a template once using a safe property path in the current data context.

Test and truthiness

test is a required, nonempty property path, such as repo.liveURL. JavaScript truthiness selects the branch: missing values, undefined, null, false, zero, NaN, and empty strings select else. Arrays and objects, even empty ones, are truthy.

No expressions, function calls, indexes, or negation syntax are supported. Invalid paths and missing required configuration fail the owning cf-data render, using its error template or default alert and error event.

Templates and scope

The first direct template without a data-state attribute is required, even for a false test. The optional first direct template data-state="else" is used when false. Other templates are ignored.

Only the selected branch is cloned and rendered. Both branches support bindings, includes, loops, and nested conditions with the current context. Conditions work inside data templates, loop rows, and fragments included in that context. Nested cf-data starts an independent scope.

Unselected templates stay inert: CFJS does not fetch their includes or data, execute scripts, apply styles, or evaluate bindings. A browser may speculatively preload literal image or script URLs in the original HTML, even inside nested templates. Use cf-src for images whose URL should only be assigned in the selected branch.

Resulting DOM and timing

The wrapper is replaced by the selected branch before mounting. False without else inserts nothing. There are no conditional load events or updates when data changes: rendering happens once.

There is no standalone conditional renderer. Data loading/error templates and loop empty templates remain static; conditions inside them are not evaluated. This feature is additive and requires no migration.
