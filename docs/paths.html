Paths and requests

Document-relative paths

Include and JSON URLs resolve against document.baseURI. For a page at /guide/index.html, ./card.html means /guide/card.html, even inside a fragment fetched from another directory or redirected URL. Includes remove URL hashes; JSON request URLs retain them.

Asset attributes are left unchanged and follow native browser rules. External CSS URLs are relative to the stylesheet; external module imports are relative to the module. Inline module imports use the document base. Active base elements inside include fragments are rejected.

Requests and caching

Request behavior by source
Source Cache Timeout
Include HTML Shared by absolute URL without hash None
cf-data src Separate JSON cache by absolute URL 10 seconds
cf-data source No CFJS cache None

The HTML and JSON caches share successful and in-flight requests for the current document lifetime. Separate live outer includes start independently; nested branches prepare sequentially; their DOM positions and script activation order remain stable. Each render creates fresh DOM. Failed requests are evicted; configuration or render failures do not invalidate a successful response. Cache mechanics are internal; no cache inspection or clearing API is supported.

Failures and constraints

HTTP(S) is required for include and JSON requests. Browser CORS, CSP, and network policy apply. Non-success HTTP status is an error; JSON also fails on invalid JSON. Include cycles, including redirects, are rejected. At most 32 fragment levels (depths 0 through 31) are prepared per branch.

Removing an element does not abort a request. There is no automatic retry, reload, or cancellation API. Use a new element to retry. Read Troubleshooting and limitations.

Successful HTML requests cache response text. Each include parses fresh markup and performs its own slot distribution, bindings, and cycle/depth checks. See fragment request caching.
