Events and lifecycle

Listen with native DOM event APIs before loading the runtime if you need to observe every event. There is no page-wide completion barrier.

cf:load

Bubbles. For a successful include, the event target is the former include parent because the wrapper has been removed. detail is { src }, using the outer element’s original source string. Nested fragments prepared within that tree do not emit separate include events. Nested data still completes independently.

For successful data rendering, the target is the retained cf-data element; there is no detail payload (event.detail === null). Both events fire after mounting and synchronous script activation, while external scripts, modules, images, and asynchronous work may remain pending.

Document readiness

Initialize ordinary page controls at DOM readiness with a deferred script or DOMContentLoaded. This does not wait for CFJS requests. Includes and data emit their own events; there is no synthetic page-wide readiness event.

cf:error

Bubbles from the failed include or data element with detail: { error }, where error is the failure object. Includes retain fallback content and log the error. Data elements replace children with the error template or default alert. A rendering failure in a loop or data-bound include belongs to its owning data element. Native script failures use normal browser error reporting.

aria-busy

A data element sets aria-busy="true" at the start of loading and removes the attribute in its finally step, after its load or error event. Includes do not set it.

data-cf-error

The failed include or data wrapper receives the error message as an attribute for diagnostics. The failure event carries the actual error. Check both the Network panel and this attribute when diagnosing a failure.

Lifetime and retry

Each element starts once. Changing attributes, removing and reconnecting it, or updating a global value does not restart it. Construct a new element using the original templates to retry. Removal does not cancel a request; disconnected data elements ignore late output, and disconnected includes ignore late successful mounting. There is no cleanup hook for timers, global listeners, or global styles.

See cf-data and cf-include for source-specific failures.
