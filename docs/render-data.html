Render JSON and global data

Load a JSON document

Use src with a JSON URL, give the response an alias with name, and bind paths inside a direct child template. Check the network response is successful JSON if rendering fails.

Use a global value or function

Assign an object, promise, or function to window before loading the runtime. Use source instead of src. Function results are awaited; functions receive no arguments or receiver. A nested data element resolves its source only on window, never from an enclosing alias. Its result template still has its own scope. A slow nested source does not delay its parent or siblings.

Module bindings and top-level let or const must be explicitly exposed on window. External scripts and modules are not a source-readiness barrier. See source.

Explain waiting and failure

Add static loading and error templates. The result below starts with a loading message and finishes with an empty-loop message. A second element demonstrates a rejected source. Reload the standalone example to see the loading state again.

For a retry, create a new data element from your original markup. Reconnecting the old one or changing its attributes will not rerender. See cf-data for caching and failure rules.

Open Loading, empty, and failure states

Use cf-if to choose a branch once in the current data or loop context. Only the selected template is rendered; nested data resolves its source on window and gives its result a separate scope. Loading, error, and loop empty templates remain static.

Data-template siblings and loop rows prepare sequentially while detached. Rows retain array order and each row keeps its own binding context. The owning data element mounts only after all preparation succeeds; scripts and styles retain document order. Nested data and unselected templates stay inert until their normal lifecycle. A failed render never mounts partial results; later siblings and rows are not prepared.
